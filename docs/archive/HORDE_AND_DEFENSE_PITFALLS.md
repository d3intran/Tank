## 1. Demo 核心目的与架构使命

从 [`ROADMAP.md`](file:///E:/UE/Tank/docs/ROADMAP.md) 中提炼出的本质：
- **游戏愿景**：**重型载具的厚重驾驶/瞄准反馈** 与 **高压密集尸潮冲垮防线的紧迫感** 相结合的防守动作射击。
- **阶段使命**：
  - **P0（已成型）**：完成高品质 C++ 驾驶闭环（1:1 厘米制量纲、负重轮物理差速、履带滚动、火炮高低机与电驱座圈平滑追踪）。
  - **P1（当前阶段）**：用“最丑的灰盒”（100 胶囊 + 方块城墙）跑通全链路，验证**“一发入魂轰散尸群、分秒必争守卫城墙”**的玩法本身是否成立。
  - **P2 / P3（未来演进）**：突破 800 只 @ 60fps 性能预算，实现伪爬墙堆叠与 VAT 顶点动画换皮。

## 2. 坑一：实体架构与规模性能陷阱

### 🔴 历史惨痛教训
1. **滥用标准 `ACharacter` + `CharacterMovementComponent` (CMC)**：
   - CMC 每帧在 GameThread 执行复杂的重力计算、胶囊地面扫掠（Sweep/Raycast）和步进检测。
   - **前人翻车点**：同屏超过 50~80 只 Character 时，GameThread 耗时直接突破 30ms，帧率跌至 20fps。试图通过“降频 Tick”优化 CMC，往往导致物理穿插和抖动，治标不治本。
2. **骨骼网格体 (SkeletalMesh) 动画求值 CPU 爆炸**：
   - 200 个骨骼网格体同时进行混合树运算与 CPU 蒙皮矩阵计算，足以让旗舰级 CPU 满载断崖式掉帧。
3. **Mass Entity 的“过度工程与通信泥潭”**：
   - 部分团队一开始就全量引入官方 MassCrowd / MassAI，发现文档极其残缺，且 Mass 与传统 Gameplay（炮弹 Hit 事件、伤害委托、UI 血条）通信极其别扭，耗费数周陷入 C++ 模板泥潭。

### 🟢 避坑对策与落地规范
* **P1 阶段绝对极简**：
  - 100 只丧尸**坚决不用 ACharacter**，直接使用最轻量的 `APawn` 或挂载碰撞的 Actor；
  - 禁用复杂物理，只在 Tick 中执行沿直线朝向城墙底部的直接坐标推进（`FVector::VectorInterpConstantTo` 或简单线性位移），地面吸附使用简单的离线高度对齐。
* **P2 阶段架构解耦（VAT + 轻量 ECS）**：
  - **渲染层**：采用 **Vertex Animation Textures (VAT) / AnimToTexture + ISM/HISM**。将奔跑、爬墙动画烘焙到贴图（顶点位置由 GPU Vertex Shader 偏移计算），**CPU 动画求值开销直接清零**。
  - **逻辑层（Lead & Filler 模式）**：800 只丧尸中，只有接触到坦克或城墙前沿的 10~20 只具备精细碰撞检测；外围 700+ 只纯粹作为流体粒子群推进。

## 3. 坑二：爬墙与堆叠技术陷阱

### 🔴 历史惨痛教训
1. **试图让 NavMesh 寻路支持垂直立面爬墙**：
   - UE 内置的 Recast NavMesh 是典型的 2.5D 高度场拓扑，天然不支持 90° 垂直立面或倒扣曲面。试图魔改 3D A* 寻路或将墙体切成极其密集的 NavMesh 连接点，会导致构建崩溃、内存暴涨，且丧尸在立面上极其容易瞬移掉落。
2. **用真实刚体物理（Chaos Ragdoll）互踩堆“尸山”**：
   - 企图让丧尸开真实碰撞胶囊，一只踩着另一只肩膀往上爬。
   - **前人翻车点**：密集堆叠时物理引擎接触点约束（Contact Constraints）爆炸，几十只丧尸疯狂抖动、高频穿模、甚至像爆米花一样被弹射出地图，算力直接耗尽。

### 🟢 避坑对策（Saber《World War Z》Swarm Engine 核心思想）
* **“Blob (聚合实体)”与分层伪堆叠**：
  - 《World War Z》开发团队在 GDC 分享表明：**尸山金字塔在宏观上不是独立个体的物理互踩，而是一个状态机聚合体**。
  - **进入攀爬区（Climb Zone）**：城墙根部放置触发盒。丧尸到达墙根后，**退出水平寻路**，直接切入“爬墙状态机”。
  - **空间排队与高度累加**：
    - 第一排丧尸停在墙根播放“撞墙/垫底”循环动画；
    - 后续丧尸到达后，直接分配一个沿墙面垂直向上的 Offset，播放 VAT 攀爬动画垂直移动；
    - 当底层丧尸被火炮轰碎时，上层攀爬者的 Offset 瞬间下坠一段距离，制造出“尸山被轰塌”的宏大视觉反馈。
  - **伤害与拆墙逻辑解耦**：城墙掉血只需按“当前处于攀爬/攻击状态的丧尸数量 × 基础伤害 × DeltaTime”计算，无需每只丧尸做真实的挥爪碰撞检测。

## 4. 坑三：火炮范围杀伤与物理检测陷阱

### 🔴 历史惨痛教训
1. **爆炸瞬间调用 `ApplyRadialDamage` 或 `MultiSphereTrace`**：
   - 一发 180m/s 的高爆穿甲弹在 200 只丧尸堆中爆炸，如果直接做球形物理重叠检测，物理引擎必须同步遍历空间 BVH 树；
   - 随之触发 50~100 个 Actor 的伤害委托、播放特效、产生力反馈——**造成极其严重的单帧卡顿（Frame Spike）**。
2. **群体死亡瞬间开启布娃娃物理（Ragdoll）**：
   - 一炮轰死 30 只丧尸，瞬间生成 30 个启用物理模拟的 SkeletalMesh。刚体之间剧烈碰撞，CPU 物理耗时当场突破 80ms。

### 🟢 避坑对策与落地规范
* **纯数学距离快速筛选（Squared Distance Filtering）**：
  - 避免对世界进行重型物理 Trace。在管理器（Horde Manager）中维护活跃丧尸坐标数组，利用简单的距离平方计算：
    $$\Delta X^2 + \Delta Y^2 + \Delta Z^2 < R^2$$
    纯纯的局部内存连续循环，一瞬间即可筛选出受击目标。
* **分级死亡表现（GPU 粒子为主，Ragdoll 为辅）**：
  - 处于爆炸核心的 80% 丧尸**直接消失/隐藏网格**，并在该位置触发一组 **Niagara GPU 爆浆与碎块粒子**（视觉极度血腥爽快，但 CPU 几乎 0 开销）；
  - 仅处于爆炸外围被冲击波掀飞的 1~2 只丧尸，才转换为带寿命的简单飞行动量或布娃娃。
* **使用 Niagara Data Channels 进行视觉广播**：
  - 不为每次击中生成独立的 Emitter Actor，而是通过数据通道将爆炸坐标与受击点传入常驻的全局 Niagara 模拟器。

## 5. 坑四：载具操控、视口盲区与关卡节奏陷阱

### 🔴 历史惨痛教训
1. **“大平地 360 度刷怪”导致的无力感与盲区焦虑**：
   - 坦克底盘厚重（转向角速度 60°/s，炮塔座圈 35°/s）。如果丧尸从 360 度空旷平原均匀涌向城墙，玩家会频繁遇到“前方炮声震天，背后城墙被拆完都没看见”的挫败感。
2. **“丧尸肉身卡车 (Body-blocking)”灾难**：
   - 如果丧尸与坦克发生双向阻挡碰撞，几十只丧尸涌上前来会像万能胶水一样把 50 吨重的坦克当场憋停在原地，甚至把坦克弹飞。
3. **装填周期 (2.5s) 与尸群涌现速度的数值错配**：
   - 一发炮弹如果装填需要 2.5 秒，但一炮只炸飞 3 只丧尸，而眼前有 100 只在快速推进，玩家会产生极度的疲劳感与无力感。

### 🟢 避坑对策与落地规范
* **漏斗形地形设计（Funneling Level Design）**：
  - 关卡切忌直接做成空旷大平地。利用残垣断壁、拒马、壕沟将四面涌来的丧尸聚拢成 2~3 条进攻主通道；
  - 创造**“把一发重炮轰进密集峡谷尸群”**的一掷千金快感。
* **单向物理压制（Crush & Push Invariant）**：
  - 坦克在撞击丧尸时，拥有绝对的物理优先级：丧尸直接被击飞（`AddImpulse`）或原地碾碎，绝对禁止微小胶囊阻挡坦克的移动阻力。
* **攻击告警与 HUD 方向指示**：
  - 屏幕边缘增加方向性警示标记。当非视野朝向的城墙被丧尸抓挠时，立刻闪烁红色警告箭头，指引玩家调转炮塔。

## 6. 坑五：独立一人开发的工程陷阱

### 🔴 历史惨痛教训
1. **自制美术黑洞**：
   - 试图自己雕刻丧尸高模、刷布料解算、手调攀爬动画，最后项目在 Blender/Maya 里消耗了 80% 的时间，玩法逻辑停滞数月。
2. **过度迷信 UE5 次世代特性**：
   - 在缺乏针对性调优的情况下盲目开启 Lumen 硬件光线追踪、超大尺寸虚拟阴影贴图 (VSM)，导致空场景显卡功耗拉满，中端机器掉帧严重。
3. **真空状态下调参（调完坦克再去调丧尸）**：
   - 孤立地把坦克的各种参数调到自己满意，等到丧尸做出来后，发现炮击溅射范围、射速、弹道速度全部与关卡节奏不匹配，全部推翻重写。

### 🟢 避坑对策与落地规范
* **严格遵守薄垂直切片铁律**：
  - **P1 阶段只用胶囊**：如果 100 个胶囊打起来不好玩，就算换成 4K 丧尸模型也绝对不会好玩；
  - **表现层严禁自制**：全部使用 Fab 免费资产与现成 Niagara 模板；
  - **新想法进 Backlog**：严格遵守每周试驾会与 Backlog 隔离机制，当期冲刺绝不临时插入新变体或新武器。

## 7. 技术选型与阶段实施对照表

| 系统模块 | 传统高危做法（踩坑） | 生产级推荐方案（避坑最优解） | 对应路线图阶段 |
| :--- | :--- | :--- | :--- |
| **丧尸实体** | `ACharacter` + 完整 CMC | P1: 轻量 `APawn` 线性推进<br>P2: `Mass Entity` 纯数据切片 | P1 → P2 |
| **人群渲染** | 独立 `SkeletalMeshComponent` | **VAT 顶点动画纹理** + `Instanced Static Mesh` (ISM) | P2 → P3 |
| **爬墙机制** | 3D NavMesh 寻路 / 刚体物理互踩 | **Climb Zone 状态机** + 垂直位移样条偏移（Blob 伪堆叠） | P2 |
| **群体伤害** | `MultiSphereTrace` / `ApplyRadialDamage` | **空间网格距离平方快速过滤** + 延迟分批结算 | P1 → P2 |
| **死亡反馈** | 每一只都生成真实物理 Ragdoll | **Niagara GPU 爆浆碎块粒子**（占90%）+ 极少量核心 Ragdoll | P1 → P3 |
| **载具碰撞** | 相互阻挡（导致坦克被卡死） | **单向碾压压制**（坦克推力无限，丧尸受力击飞） | P0 → P1 |
| **关卡地形** | 360° 空旷大平地 | **障碍聚拢漏斗（Funneling）** 汇聚尸潮波次 | P1 |

---

> **结语**：  
> 保持代码与架构的“极简与数据化”，把算力留给同屏数量与流畅帧率。让每一发重炮都能扎实地轰碎尸群，这就是本 Demo 最纯粹的立项原点。
