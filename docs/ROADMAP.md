# Tank MVP 路线图

> 愿景：驾驶坦克守卫城墙，丧尸从四面涌来爬墙——一人开发的玩法验证优先项目。
> 方法论：**薄垂直切片 + 逐层加厚**。每阶段都让"坦克→丧尸→墙"全链路以最低质量跑通，验证一个问题，达标才进下一阶段。
> 迭代顺序铁律：先迭代**乐趣**（灰盒可调）→ 再迭代**规模**（性能预算内）→ 最后迭代**表现**（现成资产）。一轮只动一个变量。

## 核心循环（不可删减的最小集）

```
驾驶坦克 → 碾压/瞄准 → 开火 → 炮弹命中 → 丧尸死亡反馈
    ↑                                      ↓
    └────── 失败/重开 ←── 城墙血量 ←── 丧尸堆山爬墙登顶
```

## 阶段规划

### P0 坦克核心循环 ✅（2026-09-06 基本完成）

- 已有：C++ 全套驾驶控制、弹簧臂相机、弹道开火、命中检测、12 负重轮差速旋转、履带 UV 滚动
- 验收：连续试驾 5 分钟不腻 ✅
- 遗留：音效/枪口焰/命中爆炸（归入 P3，不阻塞 P1）

### P1 灰盒垂直切片 ⬅️ 当前

**目标：用最丑的形态验证"轰尸潮守墙"这个玩法本身成立。**

- 内容：平地灰盒 + 城墙方块（带血量）+ 100 只胶囊丧尸直线走向墙根 + 坦克炮击杀 + 胜利/失败画面
- 明确不做：丧尸模型/动画、爬墙（先走直线）、多种丧尸、波次系统、音效
- 验收标准（DoD）：
  - [ ] 100 胶囊同屏 60fps（开发机实测）
  - [ ] 能赢也能输；输了会想"再来一把"
  - [ ] 一轮防守 3~5 分钟，节奏不冷场
  - [ ] 炮弹命中尸堆有可感知的杀伤反馈（哪怕只是一个爆浆粒子）

### P2 尸潮技术与堆爬（玩法闭环已拍板 2026-09-08）

**目标：规模与行为达标。**

**玩法闭环（拍板）**：
- 门不可破坏（纯屏障）——丧尸唯一威胁路径 = 堆山爬墙
- 登顶（越过墙顶 7.74m）瞬间消失 → 城墙 HP 扣血
- 坦克无敌：碾压 + 主炮是仅有的两种反制手段

**核心设计转念：堆不是"结构"，是"流"**——后方丧尸源源不断补位，局部杀伤只让流变稀几秒，不需要坍塌模拟（WWZ 同款原理）。假堆 = 隐形斜坡碰撞 + 沿坡面参数化攀爬（运动学，物理引擎不参与堆）。

**交互效果设计（假堆 × 任意位置打击）**：

| 交互 | 效果 |
|---|---|
| 坦克撞堆底 | 盒 overlap 判死 + 一次性碎尸（简化块 + Chaos 冲量飞溅，2s 休眠回收）；攀爬者不处理（盒高 2.36m 够不着——坦克清底部，炮清高处） |
| 炮击堆不同高度 | 径向伤害按距落点优先选受害攀爬者；半空被击杀者切"坠落态"（纯运动学重力落地 1s 消失）→ 给"打塌支撑点、上面的人掉下来"的错觉 |
| 物理成本 | 死亡碎尸并发 ≤30、存活 2~3s，Chaos 无压力 |

**关键技术约定**：
- 隐形爬坡斜坡用独立碰撞通道 `ClimbRamp`：仅丧尸攀爬查询生效；坦克碰撞、炮弹射线、瞄准视线全部忽略（否则坦克开上尸坡/被隐形墙卡死/炮弹被隐形面挡住）
- 丧尸本体灰盒 = 胶囊 + 自绘扫掠移动（与坦克同构，为 Mass 迁移铺路）

- 性能预算（先写死，所有系统在预算内做）：同屏丧尸 **800 只 @ 60fps**（开发机）
- 技术：胶囊 → Mass Entity（ISM 渲染）；丧尸 AI 用 StateTree（个体特殊行为）+ Mass（群体）
- 验收标准：
  - [ ] 800 只 @ 60fps，丧尸从四面八方汇聚不穿模、不卡死
  - [ ] 堆爬行为构成有效威胁（不碾压不炮击就持续掉城墙血）
  - [ ] 炮击尸堆不同高度 / 坦克撞堆底，反馈符合上表且打击感成立
  - [ ] 炮弹溅射 vs 单发直击的手感对比有结论

### P3 表现层换皮

**目标：从灰盒到"像一款游戏"。全部现成资产，不自制。**

- Fab 免费区：丧尸模型+共享骨架动画、枪口焰/爆炸 Niagara、开火/命中/履带/环境音效
- 丧尸模型来源清单（版权安全）：
  - **Quaternius**（quaternius.com）：CC0 低模角色含丧尸类，可商用无需署名——首选
  - **Mixamo**：免费人形模型 + 现成丧尸动画集（Zombie Walk 系列），自动重定向导出 FBX
  - **Fab / Kenney / KayKit**：免费/CC0 区按需挑
  - **Sketchfab**：CC0/CC-BY 模型（CC-BY 需署名）
  - ⚠️ **L4D2 等商业游戏 rip 素材不可用**：Valve 许可仅覆盖 Source 引擎内免费 mod，UE 项目使用即侵权
- 人群渲染路线：VAT（顶点动画纹理）或共享骨架动画，参考 OverCrowd 类方案
- 验收标准：
  - [ ] 试驾者（自己+1 位朋友）不看提示能说出"这是丧尸守城游戏"
  - [ ] 性能预算不破（换皮后复测 800 @ 60fps）

### P4 内容与平衡

- 波次设计（3 波起步）、丧尸变体 ≤2 种（快速/重甲）、简易升级或武器切换
- 验收标准：
  - [ ] 连续游玩 20 分钟有明确的"下一步目标"
  - [ ] 数值全部走 CurveTable/DataTable，改参数不重编译

## 每周试驾会（固定节奏）

1. 自己先玩一局，记录"想做的下一个动作是什么"
2. 邀请 1 位朋友玩，**闭嘴看**，只记录哪里困惑、哪里无聊
3. 产出的改动进下周期，新想法进 backlog（见下）

## Backlog 规则

- 所有"如果加个 X 会怎样"的想法 → 写进本节，不进当期迭代
- 当前 backlog：履带痕迹贴花、丧尸断肢、炮塔独立操控模式、夜战光照、音量滑条设置页

## 风险清单（按验证优先级）

| 风险 | 影响 | 验证动作 | 状态 |
|---|---|---|---|
| 大规模丧尸性能不达标 | 概念不成立 | P1 的 100 胶囊测试 + P2 前裸压力测试 | P1 内验证 |
| 爬墙行为无导航支持 | 核心威胁失效 | P2 简化贴墙状态机 | P2 验证 |
| 灰盒阶段就不好玩 | 方向性问题 | P1 试驾会 | — |
| 自制美术吞噬产能 | 项目停摆 | 纪律：表现层只允许现成资产 | 持续 |
